1What you need

  • Unreal Engine 5.8 from the Epic Games Launcher (Library → Engine Versions → +). Any 5.8.x is fine; 5.7 or older will not open the kit. Nothing else from Epic, and no Visual Studio: the game ships in the kit as a compiled module, the editor just loads it.
  • The kit, unzipped somewhere short, e.g. D:\JumperMapKit. Keep it off OneDrive-style synced folders.
  • PowerShell (comes with Windows) for the package step.
  • The game installed from Steam, to play your packaged map outside the editor.

2How a map is organised read this first

Unreal calls the container a plugin; think of it as your mod folder. One mod folder holds one map (or several), plus every asset those maps use. The mod folder's name is what the game knows you by, so you create it once and never rename it. The map inside it is a normal Unreal level file. Names can be the same; here the mod is YourMapName and so is the map. YourMapName is a placeholder: wherever you see it in this guide, use your own name instead.

JumperMapKit\
  project_jump.uproject          <- the kit (never edit this)
  Content\                       <- the game's own assets: use them, don't change them
  Plugins\
    YourMapName\                   <- YOUR MOD FOLDER (the "plugin"), made once in step 3.2
      YourMapName.uplugin          <- made for you
      Content\                   <- shows in the Content Browser as "YourMapName Content"
        Maps\
          YourMapName.umap         <- your level, step 3.4
        Meshes\                  <- anything you import or create: your choice of folders
        Materials\
        Textures\

Rule: everything you add goes under Plugins\YourMapName\Content. The kit's own Content folder holds the game's assets — use them freely, every player already has them — but don't put your own things there: the package step stops and lists anything of yours it finds in it.

3Quick start

  1. Open the kit

    Double-click project_jump.uproject. The first open compiles shaders and takes a few minutes. If the editor offers to rebuild modules, say No: that means the wrong engine version.

  2. Make your mod folder (once)

    Menu Edit → Plugins. In the Plugins window click + Add (top left). Pick the Content Only template. Fill in:

    • Plugin Name: letters and digits only, no spaces: YourMapName. This is the name forever (leaderboards, Workshop, the game's map list all hang off it).
    • Author: you. Everything else can stay as it is.

    Click Create Plugin. No restart is needed. Close the Plugins window.

  3. See it in the Content Browser

    Open the Content Browser (Window → Content Browser if it isn't already at the bottom). Click its Settings button (top right of the browser) and tick Show Plugin Content. In the left-hand tree, below Content, you now see YourMapName Content. Right-click it → New Folder → Maps.

  4. Make the level

    Menu File → New Level → Basic (floor, light, sky; easiest to start from) or Empty Level. Then File → Save Current Level As...: in the dialog, navigate into YourMapName Content → Maps, name it YourMapName, Save. Check the tab title at the top of the viewport now says YourMapName. Don't name a map after a shipped one (Aquatic, JumpLevel2, Tutorial, MainMenu).

  5. Player Start

    Open the Place Actors panel (Window → Place Actors), search "Player Start", drag it onto your floor. Rotate it to face the way players should look on spawn. Without it the game can't spawn anyone.

  6. Build

    Add geometry (section 4 says what the movement needs from it). When you import meshes or textures, or create materials, do it with your YourMapName Content folder selected in the Content Browser so they land inside your mod. Everything your map uses has to be inside your plugin folder — the package step stops if it finds assets from the kit's plain Content folder, and lists them. (Every installed map shares that one Content path in the game, so two maps with the same pack in it would overwrite each other's copies.) Fab and Megascans always import into Content, so you don't move anything by hand: just package. When the package step finds assets in Content, it offers to move them for you. Close the editor, type Y, and it moves every asset your map uses into your plugin, fixes every reference, and packages again. Assets in Content that your map doesn't use are left alone. You can also run the move on its own at any time: close the editor and double-click Tools\MoveIntoPlugin.cmd. It keeps a copy of every file it touches in Saved\MoveIntoPlugin-Backup\.

  7. Play

    Press Play (the ▶ button in the toolbar). That is the real game: real movement, HUD, saves, timer, RPG. Esc opens the pause menu (CONTROLS shows every bind), ~ opens the console. Save the level (Ctrl+S) as you go.

  8. Package it

    When it plays right, package it (section 7) and it appears in the game's map list.

4Building for the movement

The movement is built on classic jump-map physics and reads the map as brushes. What this means for geometry:

Sizes

1 game unit = 2.54 cm. Reference numbers, in both:

ThingGame unitscm
Player, standing70178
Player, crouched40102
Player radius≈13.434
Standing jump, height reached≈39≈99
Sprint jump on flat ground, no strafing≈180≈450
Useful editor grid4 or 1010.16 or 25.4

Good strafing adds a lot to the jump distance. Set the custom grid under Editor Preferences → Level Editor → Viewports → Grid Snapping ("Decimal" sizes), or just type sizes in the Details panel.

Collision

Anything the player stands on, jumps from, jumps along or bounces off needs simple collision made of boxes or convex hulls. Those are read at map load into movement brushes; on brushes, elevators and bounces behave exactly as intended, and lineups are repeatable. Rotated boxes (ramps, 45° sections) and convex hulls are brushes too, with angled faces. What can't become a brush goes through the engine's own collision instead:

Collision on the meshWhat the movement doesFeel
Box, any rotationmovement brushclean, elevators work
Convex hullmovement brush (angled faces)clean, elevators work
Sphere, capsuleengine collision (whole mesh)fine for props, no elevators
Per-triangle ("complex as simple")engine collisioncan catch and stick on edges
Geometry brushes (BSP: Box Brush etc.)engine collisionsame as per-triangle

One mesh is all or nothing: if any collision shape on it can't be a brush (a sphere or capsule), the whole mesh uses engine collision. Keep curved shapes on props you don't jump on.

Check a mesh with Show → Collision in the viewport. Cube-grid and other Modeling Mode meshes often end up with per-triangle collision, and a flat wall made that way is many small faces the player catches on mid-air: it "surfs" along instead of dropping. Open the mesh, Collision → Remove Collision, then Collision → Add Box Simplified Collision (or a convex collision); build anything that isn't one box from several boxes. Geometry brushes: select one, Brush Settings → Create Static Mesh, then give the mesh a box. Don't tick "Use Complex Collision As Simple" on anything you jump on.

To see what the movement did with your map: Play, open the Output Log and filter on CmWorld. Every converted mesh gets a line with its brush count, and every mesh it skipped gets a line saying why (e.g. "complex-as-simple", "sphere/capsule collision", "not convex"). Each skipped mesh is a surface on the engine path.

  • Bounces are the point of a jump map: a bounce is a fast diagonal landing on the edge of a box, so build bounce surfaces from clean boxes with edges on the grid.
  • Keep whole-unit sizes for ledges you intend to be exact: a 2.54 cm grid multiple. The loader snaps to a 1/16-unit grid, so small errors are forgiven, but don't build on random decimals if you want a known jump to be a known jump.
  • Falling does not kill or respawn anyone, and don't make it: leave Kill Z in World Settings at its default (a map that sets it destroys the player with no respawn). Players save and load positions, jump-server style (Save Position = V, Load Position = F by default), so design for that: obvious save spots, no soft-locks.
  • Scale test early. Drop a Player Start on your first platform and play: the pawn is the ruler. Ten minutes of jumping tells you more than any number here.

Performance

The movement runs at its own fixed rate, so frame rate does not change the physics, but keep the map cheap anyway: players want high frame rates. stat fps in the console shows what you cost. The game uses Lumen; big open landscapes with foliage are where frames go.

5Timer zones

Timed runs and leaderboards come from TimerZone actors (Place Actors → search "Timer Zone"):

  • One with Type = Start where the run begins (green wireframe). The clock starts when the player leaves this box.
  • One with Type = Finish at the end (red wireframe). The clock stops when the player enters it.
  • Half Extent is the box's half-size in cm. Make the start box cover the whole spawn platform so the run can't start early; make the finish generous.
  • Route (finish zones only): the name this finish awards. One finish, leave it on main. Several finishes = several routes with their own leaderboards: name them easy, hard, rocketless, whatever players will call them. Everyone starts from the same start box.
  • Wireframes are visible in the editor and in the game.

Every finish counts on the local leaderboard (top in the console lists it). Ignore TutorialZone: it drives the game's tutorial and is not for maps.

The map card: picture, gamemode, difficulty

The menu shows every map as a card: a square picture, the name, the gamemode and how hard it is. Give yours one. In the Content Browser, in the same folder as your level, right-click → Data Asset, pick JumperMapInfo, and name it exactly <LevelName>_Info (level Sky → Sky_Info). Open it and fill in:

  • Title: what the card says (empty = the level name). Author: you.
  • Gamemode: CJ. BHOP / SURF / KZ are listed for later.
  • Is Tutorial: tick it for a teaching map; the card says TUTORIAL instead of a difficulty.
  • Thumbnail: a square picture. Take a screenshot while playing in the editor (F9), crop it square (1024×1024 is plenty), import the PNG next to the level and pick it here.
  • Routes: one entry per finish route — the Route names from your timer zones, main for a single route — each with a Number from 1 to 10. The tier (EASY 1–3, MEDIUM 4–5, HARD 6–8, INSANE 9–10) comes from the number. The card leads with the first entry and says "+N routes" for the rest.

No _Info asset = the map still lists, with a coloured placeholder and no difficulty.

Rating a route

The rating answers one question: who can finish this route, and how long does it take them? Nothing about which tricks it uses. One number per route; the tier comes from it.

TierWho finishes it#
EASYa brand-new player1 in their first hour · 2 in their first session · 3 in their first week
MEDIUMa regular jumper4 in one sitting · 5 over a few sessions
HARDonly experienced jumpers6 in one session · 7 over a few sessions · 8 over weeks
INSANEonly the best players9 a few people have · 10 one person has, or nobody yet

Three rules: rate the route as it's meant to be played (each route gets its own number; a skip or exploit doesn't change it); a rating is a guess until people play it — if nobody finishes your "3", change the number; not sure, ask in #mapping. 0 means "not rated yet".

6Blueprints: what a map may do

Your plugin can hold Blueprints, and they run in the game: moving platforms, doors, triggers, timed sequences, sky and weather systems, widgets for on-screen text. Use anything that makes a map a map: actors, components, materials, timelines, physics, Niagara, audio, lights, fog, post process, sequencer.

The game checks every Blueprint in a map before it runs and refuses the whole map if one of them reaches for something a map has no business doing:

  • opening URLs, reading the command line, quitting the game, changing level or travelling, save games, identifying the player;
  • networking, HTTP, editor scripting, the microphone, loading assets by path at run time;
  • the game's own classes: no deriving from or calling the player, the game mode, the controller, the HUD (the map's Game Mode Override is ignored too; custom maps run the game's own mode and movement);
  • deriving from engine framework classes: Pawn, Controller, GameMode, GameState, HUD, PlayerState, WorldSettings, GameInstance.

Execute Console Command is allowed but filtered: rendering variables (fog, clouds, sky, shadows, Lumen, Niagara, foliage...) go through; anything else is dropped and logged.

The package step runs the same check and names the Blueprint and the node, so you find out at cook time, not from players. If a pack you rely on trips it for a good reason, tell us: widening a rule is a game update, not a new kit.

Asset packs from Fab (Ultra Dynamic Sky and the like) are fine as long as they are content: move the pack's folder into your plugin (right-click → Move in the Content Browser). Packs with C++ code cannot be used.

7Package it

Easiest: double-click Tools\PackageMod.cmd, type your plugin's name when it asks, done.

Or open a PowerShell window in the kit folder (the one that contains Tools; Shift + right-click the folder → "Open PowerShell window here") and run:

Tools\PackageMod.cmd -Name YourMapName -Install

(PackageMod.cmd runs PackageMod.ps1 for you. Windows refuses to run .ps1 files directly until you allow it — if you'd rather call the .ps1, run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once first.)

It validates your Blueprints, cooks your plugin against the game's shipped content (so your package holds only your assets), writes Saved\Mods\YourMapName\, and with -Install copies it to %LOCALAPPDATA%\project_jump\Mods\YourMapName\. Launch the game from Steam: your map is in PLAY, with a CUSTOM tag on its card.

The first cook takes a while (shaders). Later cooks are quick. Re-run after every change you want to test in the real game; the editor's Play button is for everything before that.

A second map, later

The command packages one mod folder — the plugin you name. The kit can hold as many as you like side by side, so a new map is a new plugin: Plugins\SecondMap, build the level there, Tools\PackageMod.cmd -Name SecondMap -Install, publish. It gets its own Workshop item, page, picture and rating; the first map is untouched. (Adding a second level inside the same plugin also works — one item then carries both maps, which suits a map pack, not two unrelated maps.) Never rename a plugin: the name is how the game and the Workshop know your mod.

8Share it on the Steam Workshop

Write the Workshop page

The first time you package, the script creates a Workshop folder in your plugin:

Plugins\YourMapName\Workshop\
  workshop.txt     the page: title, tags, visibility, description
  preview.png      the thumbnail in the Workshop list (you add it; under 1 MB, 16:9 looks best)
  Screenshots\     the gallery (you add them; .png or .jpg)

Open workshop.txt in any text editor and fill it in:

title: Sky Bounce
tags: bounce, hard
visibility: public
description:
Twelve bounces over a canyon. Two routes: the main one, and a rocketless
one for people who hate themselves.
  • visibility: public, friends, unlisted (only people with the link) or private (only you). Use private for a first test.
  • description: everything after that line, as many lines as you like. Steam's formatting works: [b]bold[/b], [i]italic[/i], [url=https://...]a link[/url], [list][*]...[/list].

Then package again with -Install, so the game sees it.

Publish

  1. Launch the game from Steam.
  2. Main menu → WORKSHOP → the UPLOAD tab. Your packaged maps are listed on the left. Pick yours: the right side shows exactly what the page will say, and anything that stops it from publishing.
  3. Press PUBLISH TO WORKSHOP. The status line shows the upload. When it's done, OPEN WORKSHOP PAGE shows the item in the Steam overlay. If Steam asks you to accept the Workshop agreement, do it there, or the item stays hidden.

Update

Change the map, package with -Install again, open WORKSHOP → UPLOAD, pick the map, write what changed in the box (it appears in the item's change notes), and press PUBLISH UPDATE.

  • An update sends the map and your note. Tick Also update the title, description... to resend the page details from workshop.txt too; leave it off if you've been editing the page on Steam instead.
  • Reset the leaderboards is your call on each update. Tick it when the update changes the course: new or moved jumps, bounces, a shortcut opened or closed. Everyone's times on the map start over, and old runs are no longer shown. Leave it off for lighting, looks or decoration: the times carry over. It can't be undone.
  • Screenshots go up with the first publish only. After that, add or remove them on the item's Workshop page.
  • The link between your map and its item is the workshop.json file in your mod folder. The package script keeps it across re-packages; don't delete it, or the next publish makes a second item.

Playing Workshop maps

Press Subscribe on a map's Workshop page — WORKSHOP → DOWNLOAD → BROWSE THE WORKSHOP opens it in the Steam overlay. The map downloads through Steam and appears in PLAY within a few seconds, with a WORKSHOP tag on its card. The DOWNLOAD tab lists what you're subscribed to, with its download state, and lets you unsubscribe.

Packaged maps only load in the packaged game. A Workshop map (or one installed with -Install) is a package; the kit's editor plays from loose files and can't mount packages, so it lists none of them. Test packaged maps in the game itself.

Without the Workshop

Zip your mod folder (Saved\Mods\YourMapName\ in the kit) and send it. Anyone who drops the folder into %LOCALAPPDATA%\project_jump\Mods\ sees the map.

9Multiplayer

Host a custom map like any other (pick it when hosting, or call a map vote). Players who don't have it:

  • Workshop maps download automatically. The lobby list marks the lobby [WORKSHOP]; clicking it downloads the map, then joins. The status line shows the progress. The map stays subscribed for them afterwards.
  • A map vote for a Workshop map starts the download for everyone who lacks it the moment the vote starts, so the map is there if the vote passes.
  • Maps that aren't on the Workshop can't be downloaded. The lobby list says "you don't have it" and joining explains why; send those players the zip.

From the kit itself, multiplayer is off — the kit's editor has the console, so it could bring cheat settings into a lobby. Play multiplayer from the Steam version of the game. For the same reason, runs you finish inside the kit go to a separate local board (Leaderboard.kit.json) and never count.

10When the game updates

A game update that changes shipped content comes with a new kit (a new Releases\<version> folder inside it). Re-run PackageMod.cmd from the new kit to re-cook your map; the map itself does not change. Packages cooked against an old release may reference things the new game no longer has.

11Troubleshooting

The editor asks to rebuild modules / "missing modules"
Wrong engine version. The kit needs 5.8.x.
My plugin folder isn't in the Content Browser
Settings → Show Plugin Content.
Map not listed in the game
Check %LOCALAPPDATA%\project_jump\Saved\Logs\project_jump.log for lines starting LogJumperMods. "no .pak files" means the cook did not produce output; "no maps.json" means the mod folder is incomplete: re-run PackageMod.cmd.
"MOD BLOCKED" in the game, or the package step fails with MODCHECK lines
A Blueprint uses a blocked node; the line names it. Remove that node.
The package step stops with "uses N asset(s) from the kit's Content folder"
Close the editor and answer Y when it offers to move them (or double-click Tools\MoveIntoPlugin.cmd). See step 3.
"Close the Unreal editor first"
The move edits your files, so the editor can't have the kit open while it runs. Save, close the editor, run it again.
Something looks wrong after a move
Every file it changed is in Saved\MoveIntoPlugin-Backup\<map>-<date>\ with its original folder layout. Close the editor and copy them back over Plugins\ and Content\.
The player falls through my floor
The mesh has no simple collision, or the collision is per-triangle ("Use Complex as Simple"). Add a box collision.
The player sticks to a flat wall and slides along it
The wall isn't a brush to the movement (per-triangle cube-grid mesh, geometry brush). See the collision table in section 3; the CmWorld log lines name the culprits.
Elevators/bounces feel wrong on one platform
Its collision isn't a brush (per-triangle, or a sphere/capsule somewhere on the mesh). Check its CmWorld line.
The WORKSHOP page says Steam refused
The game must be running through Steam, logged in to the account that owns it. If it names an agreement, accept the Workshop agreement on the item's page.
My map isn't on the WORKSHOP page, or says NEEDS ATTENTION
Package with -Install, then press REFRESH. The page lists what's missing (usually the description in workshop.txt).
A subscribed map doesn't show up
Steam may still be downloading it; give it a minute, or restart the game. If it still doesn't appear, the map was published for an older game version: ask the mapper to re-package from the current kit and publish again.
"Expected exactly one .uplugin"
The mod folder must contain only your plugin's descriptor.
The package script can't find the engine
Pass it explicitly: -Engine "C:\Program Files\Epic Games\UE_5.8".
